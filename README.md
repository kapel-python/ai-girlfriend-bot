# Telegram-бот «ИИ девушка»

Бот на Python + aiogram 3.x, создающий ощущение переписки с живым человеком:
группировка быстрых сообщений (debounce), решение модели «отвечать или нет»,
симуляция человеческого времени набора, typing-индикатор, память, настройки через меню.

## Быстрый старт

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и AI_API_KEY
python run.py
```

`.env` уже содержит ключ gptunnel из предоставленного примера — осталось вписать `BOT_TOKEN` от @BotFather.

## Как это работает

```
Telegram message
      ↓
Handler (тонкий)
      ↓
ConversationManager ── буфер сообщений + generation_id
      ↓
Debounce (по умолчанию 2.0 сек, настраивается)
      ↓
AI Service (gptunnel.ru, OpenAI-совместимый API)
      ↓
Response Decision — модель возвращает JSON {should_reply, messages}
      ↓
Typing Simulator — реалистичное время набора текста
      ↓
Telegram Sender — typing-индикатор с keep-alive, отправка
      ↓
История и факты сохраняются в SQLite
```

```
│   ├── memory.py       # краткосрочная + долгосрочная память
│   ├── typing_simulator.py  # модель человеческого времени набора

│   ├── database.py     # SQLite (aiosqlite), схема

```

## Ключевые решения

- **Нет искусственных задержек перед генерацией** — реализм создаётся на этапе
  отправки: сначала быстрый ответ модели, затем расчёт времени набора.
- **Typing почти сразу**: индикатор «печатает…» запускается сразу после debounce,
  ещё до ответа модели, и держится до отправки — как у человека, который уже
  начал отвечать.
- **Конкурентность**: каждое новое сообщение увеличивает `generation_id` и отменяет
  предыдущую задачу; необработанные сообщения возвращаются в буфер. Устаревший
  ответ никогда не отправляется. Если отправка уже началась — отправленное
  сохраняется в историю, чтобы новая генерация видела контекст.
- **Решение об ответе принимает модель** (JSON `should_reply`), а не `random()`.
  Запрос идёт с `response_format: json_object`; если модель его не поддерживает,
  клиент автоматически откатывается на обычный режим, а длинные не-JSON ответы
  нарезаются на 1–3 логических сообщения.
- **Настроение (mood)**: модель возвращает своё состояние в каждом ответе,
  оно сохраняется в БД и подставляется в промт следующих генераций.
- **Проактивность со стадиями эскалации**: если собеседник резко пропал посреди
  разговора, персонаж реагирует как живой человек:
  1. через 20–45 мин — лёгкое «ты куда пропал?» (она ещё не знает, занят он или игнорит);
  2. через 3–6 часов — вторая и последняя попытка, уже с обидкой;
  3. обе попытки проигнорированы — она замолкает, а в БД сохраняется настроение
     «недовольная, чувствует себя проигнорированной»: вернувшемуся собеседнику
     она отвечает холодно, пока модель сама не «оттает».
  Решение писать/молчать на каждой стадии принимает модель; пропущенная ею
  попытка не эскалирует. Стадия хранится в БД и переживает перезапуск; любое
  сообщение пользователя сбрасывает эскалацию (но не настроение).
- **Время суток**: в контекст каждой генерации подставляется текущее московское
  время и день недели — ночью она сонная, утром бодрее, выходные отличаются
  от будней. Часовой пояс жёстко Europe/Moscow.
- **«Доброе утро»**: если вечером попрощались и собеседник молчит с ночи
  (4+ часов), утром в окне 7:00–11:00 по Москве она может написать первой —
  решение принимает модель, одна попытка за утро.
- **Статистика в меню**: «текущие настройки» показывают сообщений в диалоге
  X/100, фактов в памяти, текущее настроение, баланс API и время у неё.
- **Промты разделены**: системный (не ломается пользователем), пресет характера,
  настроение, пользовательский — хранятся и применяются отдельно.
- **Память**: история хранится в БД полностью, в контекст модели уходят последние
  N сообщений (по умолчанию 100, `SHORT_MEMORY_LIMIT`). При пересечении лимита
  персонаж один раз честно пишет, что начинает забывать первые сообщения, и
  предлагает очистку. Плюс долгосрочные факты, извлекаемые отдельным LLM-вызовом
  раз в 3 обмена. Очистка — трёхуровневая: только диалог / диалог + память /
  полный сброс (включая настроение и стадию обиды).
- **Модели** подтягиваются из API (`GET /v1/models`), кэшируются на час,
  выбор сохраняется per-user.

## Команды

- `/start` — меню настроек
- `/reset` — очистить диалог
- `/help` — справка

Всё остальное — через inline-кнопки меню.
